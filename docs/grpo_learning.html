grpo 学习台

从直觉、公式、流程到 24 点项目落地

学习进度 1 / 6

group relative policy optimization

grpo 的核心：同一题多答几次，奖励高的答案相对变强。

它不训练 critic，而是对同一个 prompt 生成一组答案，用组内奖励均值和方差做相对优势。 对 24 点这类可验证任务，程序 verifier 可以直接给奖励，所以 grpo 特别合适。

无需价值模型 组内相对比较 适合 rule reward 需要采样覆盖

一眼看懂流程

1. 为什么不是只看绝对奖励

同一道题可能有多个答案，奖励尺度也会变。grpo 把同一 prompt 的一组答案放在一起比较： 比本组平均好，就增加概率；比本组平均差，就降低概率。

2. 为什么不需要 critic

ppo 常用价值模型估计 baseline。grpo 直接用组内平均奖励当参照，省掉 critic， 小模型和可验证任务上更轻。

3. 为什么适合 24 点

24 点答案可以程序验证：格式、数字使用、表达式合法性、结果是否为 24。 奖励不需要人工打分。

一句话记忆

grpo = 对每个 prompt 采样一组答案，用 verifier 给分，再用组内相对分数更新模型，同时用 KL 限制模型别偏离参考策略太远。

优势值

对同一个 prompt 采样 k 个答案，得到奖励 r1...rk：

a_i = (r_i - mean(r_1...r_k)) / (std(r_1...r_k) + eps)

这就是“组内相对优势”。奖励高于平均值，优势为正；低于平均值，优势为负。

策略更新

用新旧策略概率比做裁剪，避免一步更新过猛：

ratio_i = pi_new(o_i | q) / pi_old(o_i | q)
loss ≈ - min(ratio_i * a_i, clip(ratio_i, 1-e, 1+e) * a_i) + beta * kl

正优势答案希望 ratio 变大，负优势答案希望 ratio 变小。KL 项让模型保留原有语言能力。

和 ppo 的差异

点 ppo grpo
优势估计 通常依赖 value model 用同组奖励均值和方差
额外模型 需要 critic 不需要 critic
适用场景 通用 RLHF 数学、代码、可验证推理任务
核心风险 value 估计误差 采样组里没有好答案，奖励信号稀疏

训练循环

  1. 从数据集中取一批 prompt，例如 24 点数字：2, 9, 13, 13。
  2. 当前 policy 对每个 prompt 采样多个 completion。
  3. reward 函数检查每个 completion：格式、表达式、数字 multiset、结果。
  4. 对同一 prompt 的奖励做组内标准化，得到 advantage。
  5. 用 grpo loss 更新 policy，正确答案概率上升，错误答案概率下降。
  6. 用 KL 约束防止模型漂移，保存最终 checkpoint。

奖励为什么要 shaped

如果只有“完全正确才给 1”，训练早期大多数样本都是 0，模型学不到方向。 所以可以加部分奖励：格式正确、表达式合法、接近 24。

但 shaped reward 要克制

部分奖励只负责引导搜索方向，最终指标仍要看严格 verifier：数字必须恰好用一次，结果必须等于 24。

当前实验结论

贪心单次输出仍弱，solved@1 = 1/100。但模型经过 SFT + shaped GRPO 后， 在多次采样里能产生正确表达式。

单轮 best-of-128 = 78/100；多组采样合并后 89/100； 只对未解题继续 adaptive sampling 后 100/100。

这说明什么

你的模型不是“每次都能稳定想对”，而是“正确模式已经在分布里，只是单次命中率低”。 verifier-guided selection 把这些稀疏正确样本挑出来，所以 test-time compute 很有效。

组内优势模拟

调整组大小、正确答案数量和 KL 强度，观察优势值如何改变。绿色样本会被增强，红色样本会被压低。

如果一组里没有任何好答案，grpo 很难知道该往哪里走。这就是为什么 24 点项目里多采样很关键。
